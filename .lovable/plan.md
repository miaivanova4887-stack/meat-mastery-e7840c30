## Root cause

The app code is already correct — `AuthContext.tsx` passes `emailRedirectTo: https://app.carnivorex.app/auth/callback` to Supabase, and the email-hook just renders `payload.data.url` provided by Supabase Auth. So the email is being generated by **Supabase Auth itself**, and it's writing `https://carnivorex.app/auth/callback#...` because:

1. The project's **Site URL** in Supabase Auth is set to `https://carnivorex.app` (the bare apex), and
2. `https://app.carnivorex.app/auth/callback` is **not** in the Redirect URL allowlist, so Supabase silently falls back to Site URL when generating the confirmation link.

The fix is therefore mostly a Supabase Auth configuration change, plus a couple of small code hardening steps. The "user can switch to login tab and get in without confirming" issue is a separate gap: the signup flow doesn't enforce that `email_confirmed_at` is set before treating the session as valid.

## Changes

### 1. Update Supabase Auth URL configuration (config + tool)
Use the auth-config tool to set:
- **Site URL** → `https://app.carnivorex.app`
- **Additional Redirect URLs** (allowlist) → add all of:
  - `https://app.carnivorex.app/**`
  - `https://app.carnivorex.app/auth/callback`
  - `https://app.carnivorex.app/reset-password`
  - Keep existing `https://carnivore-coach-pro.lovable.app/**` and the preview `*.lovable.app/**` so dev/preview keep working
  - Keep `carnivorex://**` if any native deep-link variants are in use

This is the actual root-cause fix — once Site URL is the verified subdomain and the explicit callback URL is allowlisted, Supabase will stop rewriting links to the bare apex and the App Link will intercept on Android.

### 2. Harden `auth-email-hook/index.ts`
Even though Supabase generates `payload.data.url`, we add a defensive rewrite so a stale Site URL can never re-introduce the bug:

- Add a constant `AUTH_CALLBACK_HOST = "app.carnivorex.app"`.
- Before rendering, normalize `payload.data.url`: if its host is `carnivorex.app` (bare apex), rewrite it to `app.carnivorex.app` while preserving path, query, and `#access_token=…` hash.
- Also update `siteUrl` template prop from `https://${ROOT_DOMAIN}` → `https://app.${ROOT_DOMAIN}` so the email body links (e.g. footer/site link) point at the verified host.
- Log the rewrite when it triggers so we can confirm in Edge Function logs.

### 3. Block unverified logins (the "++" concern)
Right now a user can sign up, switch to the Login tab, and sign in with the same credentials before clicking the email link. We close that gap in two places:

**`AuthContext.tsx`:**
- After successful `signInWithPassword`, inspect `data.user.email_confirmed_at`. If it's null, immediately call `supabase.auth.signOut()` and return a synthesized error: `"Email not confirmed"`.
- Same check on the auth state listener: if a session arrives whose user has `email_confirmed_at == null` AND the source is not the `/auth/callback` route, sign out.

**`Auth.tsx`:**
- The "email not confirmed" branch already exists at line 88–89 — it will now actually fire for the switch-to-login bypass. Update copy slightly to nudge: "Please confirm your email first — we just sent the link to {email}. Tap to resend." and add a small "Resend confirmation" link that calls `supabase.auth.resend({ type: 'signup', email, options: { emailRedirectTo: 'https://app.carnivorex.app/auth/callback' } })`.

### 4. Redeploy + verify
- Deploy `auth-email-hook` so the rewrite + new `siteUrl` ship.
- Ask the user to:
  1. Trigger a fresh signup with a new email.
  2. Confirm the link in the email body now reads `https://app.carnivorex.app/auth/callback#access_token=…`.
  3. Tap it on the device — Android should open the app directly (no browser interstitial).
  4. Try the bypass: sign up, switch to Login tab, sign in before clicking email — should be rejected with the "confirm your email first" message.

## Files touched

- `supabase/functions/auth-email-hook/index.ts` — defensive URL rewrite + corrected `siteUrl`
- `src/contexts/AuthContext.tsx` — block unconfirmed sessions on sign-in and on auth state events
- `src/pages/Auth.tsx` — improved copy + "Resend confirmation" affordance
- Supabase Auth config (via tool) — Site URL + redirect allowlist
