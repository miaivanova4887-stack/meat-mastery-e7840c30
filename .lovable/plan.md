## Goal
Confirm Kotlin compilation actually runs and the `HealthConnectPlugin` class file is produced, so `MainActivity.java` can resolve the symbol.

## Verified facts
- `android/build.gradle` has `ext.kotlin_version = '1.9.25'` and the Kotlin Gradle plugin classpath. ✅
- `android/app/build.gradle` applies `kotlin-android`, sets `kotlinOptions { jvmTarget = '21' }`, and includes `kotlin-stdlib`. ✅
- `HealthConnectPlugin.kt` lives at `android/app/src/main/java/app/lovable/plugins/healthconnect/HealthConnectPlugin.kt` — package matches path. ✅
- `capacitor.build.gradle` is auto-generated by `npx cap sync` and re-opens `android {}` with Java 21 `compileOptions`. ✅

## Suspected causes
1. Stale Kotlin task outputs in `android/.gradle/` and `~/.gradle/caches/` from the pre-Kotlin builds.
2. `npx cap sync android` (run inside `build-android-fresh.sh`) potentially rewriting `app/build.gradle` and dropping `apply plugin: 'kotlin-android'`.
3. The Kotlin source set not being explicitly registered (default is `src/main/java`, but some AGP/Kotlin combos need an explicit `sourceSets.main.java.srcDirs += 'src/main/kotlin'` reassurance).

## Plan

### 1. Make the Kotlin source set explicit (defensive)
In `android/app/build.gradle`, inside the `android { ... }` block, add:

```gradle
sourceSets {
    main.java.srcDirs += 'src/main/kotlin'
    main.java.srcDirs += 'src/main/java'
}
```

This ensures Kotlin/Java co-compile from the same root the plugin file lives in, regardless of AGP defaults.

### 2. Lock the Kotlin plugin so cap sync cannot drop it
Move the Kotlin plugin application higher and add a guarded reapply at the bottom of `app/build.gradle`:

```gradle
// Top of file (already there)
apply plugin: 'com.android.application'
apply plugin: 'kotlin-android'

// At bottom, defensive
if (!project.plugins.hasPlugin('kotlin-android')) {
    apply plugin: 'kotlin-android'
}
```

### 3. Add a Kotlin compilation guard to the build script
Update `scripts/build-android-fresh.sh` to:
- After `npx cap sync android`, `grep` for `apply plugin: 'kotlin-android'` in `android/app/build.gradle` and re-add it if missing.
- Before `assembleDebug`, run `./gradlew :app:compileDebugKotlin --no-build-cache --rerun-tasks` and abort if it fails or produces zero `.class` files in `android/app/build/tmp/kotlin-classes/debug/app/lovable/plugins/healthconnect/`.
- Wipe `android/.gradle/` and `android/app/build/` before `clean` to remove stale Kotlin task descriptors.

## Why this resolves the cryptic Java error
If `compileDebugKotlin` runs and produces `HealthConnectPlugin.class`, `compileDebugJavaWithJavac` will see it on the classpath via the standard Kotlin → Java compile order (KAPT stub generation puts Kotlin classes in scope before Javac runs). The current symptom — Java not finding the class even though the `.kt` exists — means Kotlin compile is being skipped or its output is being discarded; the explicit source set + plugin guard + script-level verification eliminates all three suspected causes at once.
